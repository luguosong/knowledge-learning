# 主题文章作为唯一正文

原有记录与站点文章分别保存知识正文，需要持续整理两套内容。统一后，主题文章保存唯一正文，同时供 AI 代理维护和读者浏览。2026-11-01 已完成正文、工具和运行指引迁移，旧正文目录已退役。

## 已确认的决策

- 主题文章是知识正文的唯一事实源。一篇文章可以回答多个问题。
- 专题导读负责组织文章与链接，不重复保存完整解释。
- AI 代理继续修改仓库中的 Markdown，站点负责浏览、搜索与导航。
- 本次统一不增加网页编辑与保存能力。

## 提问记录与证据

- 在文章末尾保存提问记录，包括原问、必要约束、原问题 ID、日期和相关章节链接。
- 一个问题涉及多篇文章时，指定唯一主文章保存提问记录，并链接其他文章。
- 同一问题的追问沿用原 ID，更新相关正文和提问记录。语义独立的问题才分配新 ID。
- 来源、适用条件、局部核实范围和修正历史随对应正文保存，不另存一份答案。
- 保留首次提问日期、实际知识更新日期和核实日期。迁移日期不替代这些日期。

## 范围与综述

- 将领域范围和综述并入对应文章的导语或专题导读，供读者和 AI 代理共同阅读。
- 单篇主题由文章导语承接；多篇主题由导读组织。不为每个旧领域强制新增导读。
- 保留先定位范围、再读取概览和相关章节的检索方式。
- 名称、别名、目录及反向链接可以作为派生索引，不另行改写知识正文。

## 迁移基础

- 以现有站点文章为基础，保留阅读结构和图表。
- 逐项对照原记录，补齐来源、核实范围、适用条件、追问与修正历史。
- 差异逐项核对。事实冲突按证据处理，不因选定文章结构而直接覆盖记录结论。
- 原记录在验收通过后退役。

## 旧入口与附件

- 保留旧标题、原问题 ID 到文章章节的可检索映射。
- 不保留旧本地路径和旧 wiki 链接直接打开的能力。迁移后的内部链接全部更新。
- 继续采用标准 Markdown 相对链接；沿用既有站点 URL 不额外重定向的规则。
- 将必要附录、来源原件和演示附件迁入站点，由文章链接访问。
- 附录按内容并入文章，或保留为独立补充页。来源原件、脚本和实验轨迹作为附件保存。
- 管理日志、备份和迁移清单保留在维护区域，不进入内容导航。

## 迁移与验收方案

1. 保存迁移前快照、文件清单与哈希。验证：快照和清单可以对应原文件。
2. 分领域核对两套内容，迁移正文、提问记录和必要附件。验证：每个原问题都有唯一主文章。
3. 核对来源、适用条件、核实范围、日期和修正历史。验证：差异有明确处理结果，迁移没有刷新知识日期。
4. 调整检索、关联与校验工具。验证：可以按主题、旧标题、原问题 ID 和章节定位内容，内部链接和附件有效。
5. 完成全库验收后一次切换正式流程，退役旧正文和二次改写链路。验证：严格构建通过，运行入口只维护统一模型。

## 沿用的运行规则

- 保留按范围检索、局部读取、正向关联与反向链接的能力。
- 目录、统计和反向链接从源内容派生，不另行人工维护。
- 继续按既有规则组织专题、拆分和合并文章；结构变更同时迁移提问记录并更新链接。
- 继续在问答后自动提交、推送并由 Pages 发布；提交范围限于本次任务的变更。
- 发布以校验通过为前提。失败时保留本地改动，按现有规则处理冲突和推送失败。

## 取舍

- 采用主题文章，保留连贯阅读与现有专题组织。
- 不采用“一问题一页”作为正文单位。提问记录保留来由，主题文章保存完整解释。
- 不保留记录正文到站点文章的二次改写链路，避免继续维护两套答案。
- 保留旧入口的检索线索，放弃旧本地路径直接打开的能力，以便退役旧目录。
