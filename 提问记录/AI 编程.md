# AI 编程

## 综述

编程智能体通过读取项目、修改文件、调用工具和验证结果形成闭环。选型先比较终端、IDE、桌面、云端及应用构建平台的入口和工作方式，再以实际仓库验证质量、耗时、费用与地区可用性；旧清单不作为当前排名。OpenCode 的模型可用性取决于已配置提供商。ZCode 的桌面打包与 CLI 分发方式分别理解。WASM 可以封装为 MCP 工具，其隔离与系统能力依赖宿主；云端并发仍需设计状态、认证和资源约束。MCP 启动命令、传输方式、部署位置与并发能力是不同维度；本地服务器权限和远程数据暴露需分别评估。Codex 的完整访问设置涉及命令审批和沙箱，具体配置及产品变更按问题日期重新核实。Codex 桌面与 CLI 共享代理框架，主要差在项目管理、预览与浏览器交互，以及终端脚本和 CI 集成；不能按入口推定编程强弱。跨工具 Skill 格式与发现路径分别核对；多种工具支持项目 `.agents/skills`，Claude Code 官方列 `.claude/skills`，发现描述不等于正文常驻或必然调用。比较 ZCode 与 Claude Code 时应固定模型；GLM 价格不能算作 ZCode 独有优势。ZCode 已有手机远控、本地定时与聊天渠道；闲时任务可为符合资格的套餐用户节省额度，但有排队、模型与本地执行限制。同模型下的任务收益仍需实测。
