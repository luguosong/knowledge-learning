# RPC

## 综述

远程过程调用（Remote Procedure Call，RPC）让程序以调用函数或方法的形式，请求另一个进程执行操作；两个进程可以位于不同计算机。典型的一次请求、一次响应过程是：客户端把方法标识与参数编码为消息，服务端解码并执行方法，再把结果或错误传回客户端。RPC 是通用调用机制，具体协议各自定义消息格式与语义；例如 ONC RPC 有独立协议规范，gRPC 是具有自身协议的 RPC 框架。超文本传输协议（Hypertext Transfer Protocol，HTTP）是应用层通信协议，规定请求方法、请求与响应、头字段、状态码等通用语义；RPC 可以通过 HTTP 实现，gRPC 的协议基于 HTTP/2，JSON-RPC 也允许以 HTTP 承载。按资源组织的 HTTP 接口与按业务方法组织的 RPC 接口是接口设计上的比较；HTTP 接口可以采用 RPC 风格，不能把 HTTP 等同于资源式接口。gRPC 等框架统一服务接口、消息编码与调用状态，并可生成两端代码；HTTP 接口也可以借助 OpenAPI 生成客户端，方法式调用写法不能单独判定接口风格。框架可以封装通信细节，但远程调用仍有编码与网络开销，以及独立的网络、服务端故障；调用超时不代表服务端未执行，重试可能重复操作。
