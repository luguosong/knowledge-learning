# 容器编排

## 综述

K8s 是声明式 API + 控制循环的容器管理平台（Google 2014 年开源，源自内部 Borg 经验，CNCF 托管）：声明期望状态，控制器持续把集群现实收敛到期望，据此自动完成部署、扩缩容、自愈与流量分发。与 Docker 曾绑定（kubelet 内置 dockershim）、后经 CRI 标准解耦（1.24 移除 shim）；今日分工——Docker 造 OCI 镜像，集群用 containerd 跑镜像。

## 2026-09-21 · 什么是 Kubernetes
- **问**：什么是 k8s
- **答**：K8s 是 Google 2014 年开源（源自内部集群系统 Borg 的经验）、现由 CNCF 托管的容器管理平台。核心机制是声明式 API + 控制循环：你声明期望状态，控制器持续把集群现实收敛到期望，从而自动完成部署、扩缩容、自愈与流量分发。官方文档甚至刻意不以"编排"自称。
- **信源**：[一手] https://kubernetes.io/docs/concepts/overview/ · [一手] https://kubernetes.io/blog/2015/04/borg-predecessor-to-kubernetes/ · [一手] https://cloud.google.com/blog/products/gcp/from-open-source-to-sustainable-success-the-kubernetes-graduation-story

## 2026-09-21 · k8s 和 Docker 的关系（承接上条）
- **问**：k8s 和 docker 之间是什么关系
- **答**：曾绑定、后解耦。早期 k8s 靠 kubelet 内置的 dockershim 直接调 Docker 跑容器；2016 年 k8s 1.5 引入 CRI 标准接口，2017 年 Docker 把核心运行时 containerd 捐给 CNCF；2020 年（1.20）弃用、2022 年（1.24）移除 dockershim，此后集群直接用 containerd/CRI-O，与 Docker 无直接依赖。但 Docker 构建的镜像本就是 OCI 镜像，集群照常运行——今天的关系是"开发用 Docker 造镜像，集群用 containerd 跑镜像"。
- **信源**：[一手] https://kubernetes.io/blog/2020/12/02/dont-panic-kubernetes-and-docker/ · [一手] https://kubernetes.io/blog/2020/12/02/dockershim-faq/ · [一手] https://www.cncf.io/blog/2017/03/29/containerd-joins-the-cloud-native-computing-foundation/
