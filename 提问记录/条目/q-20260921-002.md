# 2026-09-21 · Cookie/Session/JWT 算不算认证技术

- **问**：cookie、session、JWT 这些算用户身份认证技术吗？
- **答**：Cookie 是浏览器状态载体，Session 是会话管理机制，JWT 是可用于多种场景的声明格式，三者不等价，也都不能单凭名称视为用户认证协议。JWT 不必然是 Bearer Token；OIDC 的 ID Token 采用 JWT 格式，访问令牌则可采用 JWT 或不透明格式，DPoP 等机制可以将访问令牌绑定发送方。
- **旧答（部分已被 2026-09-22 修正）**：算演化史的配套层，但严格分类属于**会话管理**——认证（一次性验明正身）之后，如何在无状态的 HTTP 上延续身份。两条主线：①cookie 载体（1994 Netscape Montulli 为购物车发明，RFC 6265 2011 年标准化，6265bis 草案加 SameSite 等）；②状态放哪的权衡——服务器端 session（可撤销、有状态）vs JWT（RFC 7519 2015，无状态、难撤销）。JWT 本质是 bearer token（谁持有谁能用），泄露即冒用——与密码同属"持有人凭证"弱点；会话层自身的演化方向与认证主线一致：DPoP（RFC 9449 2023）用客户端私钥绑定令牌，偷走也没用。OIDC 的 ID Token 就是 JWT，故这层贯穿第三~六代，是基础设施而非新的一代。
- **修正**：旧答中的“JWT 本质是 bearer token”混淆格式与使用方式；“DPoP 令牌偷走也没用”只适用于攻击者无法取得或调用绑定私钥等条件，不能保证客户端被控制时仍安全。旧答其余历史日期未在本次重新核实。
