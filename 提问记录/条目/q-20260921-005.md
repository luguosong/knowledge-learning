# 2026-09-21 · Claude Code subagent 的使用、配置与执行原理

- **问**：详细讲解 Claude Code 中 subagent 的使用方法、配置方式、执行过程以及原理。追问：深入学习讲解 Claude Code 中的 subagent 用法。
- **答**：subagent 是拥有独立上下文、指令和工具配置的委托执行实例；普通实例不继承主对话历史，应以目标、范围、必要背景、约束与证据要求定义任务，并由主 agent 综合结果、完成验收。按 2026-10-07 官方文档，应区分普通 subagent、继承历史的会话 fork、skill 的隔离执行、恢复同一实例与持久记忆；上下文隔离不等于文件隔离或总费用降低。
- **历史结论（已被 2026-10-07 修正，具体修正见下）**：subagent 是由主对话派生、拥有独立上下文窗口的专职 agent，核心动机是隔离上下文污染（挤占预算、稀释注意力、推高成本）。执行：主 agent 依据各代理 description 决定委派 → Agent tool 派生 → 子代理冷启动（自身 system prompt + 任务消息 + CLAUDE.md + git 快照，不继承对话历史）→ 工具循环（两道工具过滤器 + 独立权限，提示上浮主会话）→ 输出扫描防提示注入 → 回传摘要 + agent ID（可用 SendMessage 带全历史续聊，保留热 prompt cache）。默认 3 层嵌套、20 并发；fork（/subtask）是唯一继承父历史的例外。配置：.claude/agents/（项目）与 ~/.claude/agents/（用户）下的 Markdown + frontmatter，仅 name、description 必填，description 驱动自动委派，model 解析顺序为 调用参数 → frontmatter → CLAUDE_CODE_SUBAGENT_MODEL → 主对话模型；缺 name/description 的文件被静默跳过。使用：自动委派（最常用）、@-mention（保证触发）、claude --agent <name>（整机替换）；内置 Explore（只读探索）/Plan（计划调研）/general-purpose。
- **校正与深化**：
  - 启动上下文存在例外：Explore 与 Plan 跳过 CLAUDE.md 和 git status；自定义代理可以用 `omitClaudeMd` 跳过用户、项目与本地 CLAUDE.md。普通代理不继承主对话已读文件、已调用 skill 的内容或主会话 auto memory；关键任务背景必须明确传递。
  - 交互式 CLI 中，自然语言命名由模型决定是否委派，@ 选择 agent 保证调用该角色；`--agent` 将主会话配置为该角色，`--agents` 定义本次会话可用的角色。`/agents` 从 v2.1.198 起只打印创建／维护提示；v2.1.197 及以前提供交互界面。
  - 当前默认嵌套深度 3、同时运行上限 20 已重新核实；分别由 `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` 与 `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` 控制。并发限制约束 Agent tool 新派生；手动 fork、恢复实例和 ultracode 等存在例外，不能概括为绝对上限。
  - 模型通常依次取本次调用参数、代理定义、`CLAUDE_CODE_SUBAGENT_MODEL`、主会话模型；`CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` 可强制覆盖，fork 等仍有例外。不要把 Explore 固定理解为 Haiku；当前文档按主模型与接入方式定义其模型。
  - 前台执行阻塞主会话，后台执行允许继续工作；当前交互式 fork mode 默认开启并使新派生在后台运行。后台权限请求会显示在主会话；`/tasks` 用于查看和管理。后台不是取消权限检查。
  - 每次新调用建立新实例；恢复有 ID 的原实例可保留其历史，Explore 与 Plan 当前是一次性代理，不能恢复。`memory` 才用于跨会话持续记录；角色文件本身不保存历次任务历史。
  - 会话 `/subtask` 继承完整历史，skill 的 `context: fork` 创建独立上下文且不继承历史。`skills` 预加载完整 skill 内容，但不等于可访问 skill 的白名单。
  - 默认共用工作目录；并行写代码应划分文件所有权，必要时用 `isolation: worktree`。worktree 默认从仓库默认分支创建，可用 `worktree.baseRef: head` 从当前提交创建；未提交改动不会因此自动复制。
  - 只读审查示例使用 `tools: Read, Grep, Glob`。仅移除 Write／Edit 仍可能通过 Bash 或 MCP 写入；启用 `memory` 会自动增加 Read／Write／Edit。工具可用性、权限审批与文件隔离应分别考虑。
  - 原“输出扫描防提示注入”表述过强：扫描转义部分仿冒标记并标注指令形态，不判定内容是否恶意，也不能代替权限或沙箱。报告应带文件位置、触发条件、验证结果与未核实项；摘要不是正确性证明。
  - 定义位置共五层，优先级为托管 `.claude/agents/` → `--agents` 会话级 → 项目 → 用户 → 插件 `agents/`；目录递归扫描，嵌套项目目录中同名定义以离工作目录最近者为准；格式缺陷文件被静默跳过，可用 `claude plugin validate <dir>` 检查。
  - 字段全景（15+）：`disallowedTools` 先于 `tools` 应用，`Bash(git push *)` 类条目移除整个工具；`permissionMode` 在主会话处于 bypassPermissions/acceptEdits/auto 时被忽略，子代理不能自声明 bypassPermissions；`maxTurns` 截断输出并标记 partial、可续；`effort`（low/medium/high/xhigh/max）；`memory`（user/project/local，注入 MEMORY.md 前 200 行或 25 KB）；`mcpServers`（内联定义需目录信任）；`hooks`（Stop 映射为 SubagentStop）；`isolation: worktree`；`background`；`initialPrompt`；`experimental.cacheTtl`（5m/1h）；`skills` 不能预载 `disable-model-invocation: true` 的技能。
  - 所有代理 description 合计超 15,000 tokens 触发启动警告——description 是委派路由表，数量与长度都有代价。
  - 后台 subagent 仅保留精简内置工具集（Read/Grep/Glob/LSP/Bash/PowerShell/Edit/Write/NotebookEdit/WebFetch/WebSearch/TodoWrite/Skill/ToolSearch/EnterWorktree/ExitWorktree/Monitor/TaskStop/SendMessage/Artifact/SubagentHandback）加 MCP 工具；Ctrl+B 把前台任务转后台。
  - 冷启动还注入兄弟代理名单（sibling roster）；不继承 output style 与父上下文窗口尺寸（按自身模型决定）；`cd` 不跨 Bash 调用保留；扩展思考自 v2.1.198 起继承。
  - coordinator 模式：`tools: Agent(worker, researcher), Read, Bash` 以白名单限制可再派生的代理，仅适用于 `--agent` 主线程。
  - 子代理 transcript 位于 `~/.claude/projects/{project}/{sessionId}/subagents/agent-{agentId}.jsonl`，按 cleanupPeriodDays（默认 30 天）清理。
  - 会话 fork 命令现名 `/subtask`（v2.1.212+；v2.1.161–2.1.211 为 `/fork`）。
  - agent teams 为实验特性：`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` 开启；一个会话一个团队，队友不能再派队友，lead 固定，subagent 定义中的 `skills` 字段不作用于队友。官方对比：subagent 适合“只需要结果”的任务且更省；teams 适合需要讨论协作的工作且成本更高。
