# 2026-10-10 · MinIO 公司是否倒闭或停止经营

- **问**：minio 这个公司是倒闭不干了吗？追问：有什么替代方案吗？再追问：minio 平替或更优解？本次追问：除了 https://github.com/pgsty/silo，还有没有 MinIO 的平替或相关项目，用于项目中文件管理？
- **答**：MinIO 的 AIStor 商业线仍有公开活动，原开源仓库已停止维护；Silo 延续 MinIO，但当前已发布 Server 为 20260903。除 Silo 外，项目文件存储可以按场景评估 SeaweedFS、RustFS、VersityGW、Garage；如果需要现成的用户文件管理与分享系统，可以评估 Cloudreve，如果 Java 项目需要统一存储接口，可以评估 X File Storage。
- **信源**：原问题一手资料：[MinIO 官方开源仓库及停止维护声明](https://github.com/minio/minio)、[AIStor 官方下载与订阅说明](https://www.min.io/download)、[AIStor 升级文档与免费许可证说明](https://docs.min.io/aistor/administration/upgrade-aistor-server/)、[Ceph Object Gateway 官方文档（Tentacle）](https://docs.ceph.com/en/tentacle/radosgw/)；本次已核实的一手资料见下方各项目证据。
- **更新**：2026-10-13

### 本次选型说明与证据（2026-10-13）

- **SeaweedFS**：独立对象与文件存储系统，Apache-2.0；支持上传、下载、分片上传、预签名链接、CORS、桶策略、对象版本与对象锁。官方 `weed mini` 将各组件放在一个进程，适用于单节点和小集群文件存储，但只运行一个 master；多 master 高可用需要分组件部署。架构包含 master、volume、filer，适合希望从单节点逐步扩展的业务文件服务。当前官方 wiki 的接口清单属于持续更新文档，不能直接当作 4.48 的完整交付清单。最新发布为 4.48，仓库与发布活动持续；本次未独立验证指定版本的全部接口、性能或可靠性。[一手] [官方仓库](https://github.com/seaweedfs/seaweedfs)、[Apache-2.0 LICENSE](https://github.com/seaweedfs/seaweedfs/blob/master/LICENSE)、[S3 接口与语义差异](https://github.com/seaweedfs/seaweedfs/wiki/Amazon-S3-API)、[weed mini 用途与单 master 限制](https://github.com/seaweedfs/seaweedfs/wiki/Quick-Start-with-weed-mini)、[4.48 发布页](https://github.com/seaweedfs/seaweedfs/releases/tag/4.48)。
- **RustFS**：独立 S3 对象存储，Apache-2.0；官方于 2026-09-16 宣布 1.0.0 正式发布，最新发布为 1.0.1。1.0.1 标签内兼容矩阵确认核心对象操作、分片上传、预签名 GET/PUT、桶策略，以及部分版本、对象锁、CORS 行为；矩阵明确只保证已覆盖的功能，不宣称完整 S3 兼容。ACL 授权是有意不支持；桶访问日志、POST 表单上传校验和、桶所有权控制等仍存在未通过或未实现范围。当前 main README 的 Available/Preview 清单属于主分支，不能直接当作任一已发布二进制的完整交付清单；官网兼容文档注明采用 2026-08-09 提交快照，也须与发布标签区分。MinIO 磁盘兼容在 main 标为 Preview 且默认构建未启用，不能据此承诺原地迁移；主分支说明还明确不能读取 MinIO 加密对象。可以评估其管理控制台与宽松许可证，但正式版本历史较短，业务应验证实际 SDK、权限和恢复流程；“成熟度优于其它项目”未核实。[一手] [官方仓库与状态清单](https://github.com/rustfs/rustfs)、[Apache-2.0 LICENSE](https://github.com/rustfs/rustfs/blob/main/LICENSE)、[1.0.0 正式发布公告](https://rustfs.com/blog/announcing-rustfs-1-0-0-ga/)、[1.0.1 发布页](https://github.com/rustfs/rustfs/releases/tag/1.0.1)、[1.0.1 标签内 S3 兼容矩阵](https://github.com/rustfs/rustfs/blob/1.0.1/docs/architecture/s3-compatibility-matrix.md)、[官网兼容文档及快照日期](https://docs.rustfs.com/en/reference/s3-compatibility)。
- **VersityGW**：Apache-2.0 的 S3 网关，可把本地目录或挂载目录暴露为 S3 服务；网关自身无状态，数据保护与容灾由底层存储承担。如果项目已有可靠的本地存储或 NAS，而目标是复用 S3 SDK，可以评估；POSIX 后端的对象版本功能仍标为 experimental，不能把它当作自带分布式复制的完整对象存储系统。[一手] [官方仓库](https://github.com/versity/versitygw)、[POSIX 后端及版本限制](https://github.com/versity/versitygw/wiki/POSIX-Backend)。
- **Garage**：轻量、自包含的分布式 S3 对象存储，AGPL-3.0；官方镜像仓库说明作者自 2020 年起用于生产服务，官方发布列表最新为 v2.4.1（2026-09-08）。支持核心对象操作、分片上传、预签名链接与 CORS，适合不需要复杂 S3 权限和历史版本的小型业务或异地副本。官方兼容表明确不支持对象版本、S3 桶策略、访问控制列表（Access Control List，ACL）、对象锁、S3 桶复制接口及标签；授权使用每访问密钥与每桶的自有机制。Garage 集群内部副本与 S3 桶复制 API 是不同能力，不能写成“不支持任何复制”。[一手] [官方 GitHub 镜像](https://github.com/deuxfleurs-org/garage)、[AGPL-3.0 LICENSE](https://github.com/deuxfleurs-org/garage/blob/main-v2/LICENSE)、[官方功能说明](https://garagehq.deuxfleurs.fr/documentation/reference-manual/features/)、[官方 S3 兼容表](https://garagehq.deuxfleurs.fr/documentation/reference-manual/s3-compatibility/)、[官方发布列表](https://garagehq.deuxfleurs.fr/_releases.html)。
- **Cloudreve**：GPL-3.0 的完整自托管文件管理与分享系统，支持本地和 S3 兼容存储、用户组、预览与到期分享链接。如果“文件管理”指用户登录、目录浏览、预览和分享，可以评估；官方明确它不是其它网盘的管理器，不能让其它文件管理器同时直接管理 Cloudreve 底层文件。[一手] [官方仓库](https://github.com/cloudreve/Cloudreve)、[官方文档](https://docs.cloudreve.org/en/)、[API 与底层文件管理边界](https://docs.cloudreve.org/en/api/overview)。
- **X File Storage**：Apache-2.0 的 Java/Spring Boot 存储适配库，统一本地、S3 兼容和云存储接口，提供分片上传与预签名链接能力。它适合业务代码统一上传和下载接口；它不是对象存储服务，也不直接提供用户文件管理系统。[一手] [官方仓库](https://github.com/dromara/x-file-storage)。
- **Silo 发布边界修正**：旧结论“最新版 2026-09-16 发版”与“2026-09-16 发版、仓库活跃”**已被 2026-10-13 修正**。官方 README 当前明确最新已发布 Server 为 20260903；2026-09-16 说明 main 有尚未进入 Server 发布的安全、存储与 Console 改动，不能把说明日期或主分支提交日期当成发布日。[一手] [Silo README 的 Current release and main branch](https://github.com/pgsty/silo#current-release-and-main-branch)。
- **RustFS 概括修正**：旧综述“纠删码/bitrot/版本控制/对象锁/复制齐备”**已被 2026-10-13 修正**。新结论按具体发布标签、测试范围与构建开关说明能力；官方功能清单、已实现处理函数和已通过兼容测试是不同证据，不能仅凭 main 的功能标签认定发布版本完整支持全部 S3 语义。[一手] [1.0.1 标签内 S3 兼容矩阵](https://github.com/rustfs/rustfs/blob/1.0.1/docs/architecture/s3-compatibility-matrix.md)。
- **条件与待确认**：本次只核实官方文档、仓库与发布页面，未下载、部署或实测。选择取决于单节点或集群、数据规模、现有存储、后端语言、是否需要用户文件管理界面，以及是否需要版本、锁和复杂权限；以上尚未由用户说明，不能据此确定唯一方案。
