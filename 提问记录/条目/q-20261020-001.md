# 2026-10-20 · 将 WASM 封装为 MCP 供 Agent 调用的可行性与形态

- **问**：是否可以将 WASM 封装成 MCP 供 agent 调用？
- **答**：可以，三种形态均已落地：① 自建宿主——用 MCP SDK 写服务器，在工具 handler 内经 Wasmtime/Extism 调用 WASM 导出函数；② 通用插件型服务器——微软 Wassette（Wasmtime + WIT 接口→MCP 工具，OCI 分发，默认拒绝授权）与 hyper-mcp（Extism 插件，可配 allowed_hosts/memory_limit，sigstore 签名；原仓库 2026-01-11 归档并迁移）；③ 服务器整体编译为 WASM——Spin/Wasmcp 把工具与中间件组合为单个 server.wasm，导出 wasi:cli/run（stdio）或 wasi:http/incoming-handler（Streamable HTTP）。可行性的根据：MCP 规范只定义 JSON-RPC 消息与传输绑定，明确 transport-agnostic，不约束服务器实现技术。收益是能力式沙箱与 OCI 小体积分发；限制是系统能力须宿主显式授予、移植到组件模型有门槛、会话与授权在各运行时实现碎片化。
