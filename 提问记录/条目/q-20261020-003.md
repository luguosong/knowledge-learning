# 2026-10-20 · DWG 处理 WASM 云端部署的并发与 C++ 替代问题

- **问**：处理 DWG 文件的 WASM 放云端会不会有并发/多人同时使用问题？云端是不是可以直接用 C++，都没必要用 WASM？
- **答**：并发与 WASM 无关。Wasmtime 官方语义：每个实例独占线性内存，Store 是隔离边界，不同 Store 的实例可跨线程并行，Engine（编译产物）线程间共享、模块只编译一次；按请求实例化即请求间零共享、天然隔离可扩展。DWG 处理"传文件回结果"天然无状态，MCP 协议本身也无状态；多人并发是普通后端问题（水平扩展、网关认证限流、单实例内存/时间限额）。旧结论“单个 stdio MCP 服务器进程内的工具调用在该实例内串行排队”已被 2026-10-25 修正：stdio 只规定共享通道、消息分帧和按请求 ID 关联结果，并不强制工具串行；实际并发取决于 SDK、处理函数和资源限制。C++ 替代：可信用户＋自有服务器时直觉正确，原生更简单且无 WASM 开销（官方称接近原生，具体百分比未实测）；公网接收不可信 DWG 上传时 WASM 内存沙箱仍有真实价值——DWG 解析器是内存安全重灾区（已核实 LibreDWG CVE-2025-61154：decode.c 的 decompress_R2004_section 堆溢出，恶意 DWG 触发 DoS，CVSS 6.5；另检索命中 CVE-2026-15520/9502/9602 同类），原生堆写溢出最坏可升级为代码执行，WASM 中溢出被限制在线性内存内、最多该请求崩溃。次级价值：每请求一实例的隔离密度比容器便宜（ResourceLimiter、PoolingAllocator 为此设计），同一 .wasm 跨本地/边缘/云端复用。
