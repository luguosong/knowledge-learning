# 2026-10-29 · JVM 跨平台与 HotSpot 运行时优化的机制

- **问**：解释 Oracle 教程原文：JVM 可运行于多种操作系统，同一 .class 文件能在 Windows、Solaris OS、Linux、Mac OS 上运行；HotSpot 等虚拟机在运行时执行额外步骤提升性能，包括查找性能瓶颈、将频繁使用的代码段重新编译为本机代码。
- **答**：这段话讲两层机制。跨平台：javac 把源码编译为平台无关的字节码（bytecode），各操作系统各自移植 JVM，把同一份字节码翻译为本机代码；前提是目标系统装有对应 JVM，代价是比直接执行本机代码多一层翻译。HotSpot 运行时优化：“查找性能瓶颈”即运行时性能分析（profiling），“重新编译为本机代码”即即时编译（Just-In-Time Compilation，JIT）；不在编译期全部编译为本机码，是为了保住跨平台并利用只有运行时才有的信息（热点、类型分布）。HotSpot 用分层编译：C1 快速编译并采集信息，C2 据此深度优化。教程以“一些虚拟机”限定，因为 JIT 属实现行为，JVM 规范将指令优化留给实现。
