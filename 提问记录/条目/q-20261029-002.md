# 2026-10-29 · ZCode 与 Claude Code 的当前差距

- **问**：ZCode 现在和 Claude Code 之间存在差距吗？
- **答**：应分开比较工具与模型；Claude Code 可按智谱官方教程接入 GLM，所以 GLM 的模型价格和可用性不能直接算作 ZCode 的独有优势。本次核实到的具体使用理由是 ZCode 的闲时任务：符合资格的 Coding Plan 订阅用户可排队执行不紧急的本地任务，自动执行不消耗套餐额度，但开放范围、排队、模型选择和电脑保持唤醒均有限制；本次未核实同模型、同任务下的质量或效率优势。

- **信源**：[一手] [zai-org/ZCode 仓库](https://github.com/zai-org/ZCode)（Apache-2.0、三形态、v3.16.2、8.3k stars）；[一手] [ZCode 官方问答](https://zcode.z.ai/cn/docs/qa)（智能体开发环境、工具免费、模型自配）；[一手] [Claude Code 概览](https://code.claude.com/docs/en/overview)（入口、能力、模型要求、发布节奏）；[一手] [Anthropic 2025-02-24 公告](https://www.anthropic.com/news/claude-3-7-sonnet)（Claude Code 以 limited research preview 发布）；模型对比数据沿用 [[条目/q-20261008-003|2026-10-08 · GLM 5.3 Flash 与 Haiku 5.5、GPT-6 Luna 对比图总结]]（仅小模型层）。

### 分维度对比

#### 产品形态：差距已基本对齐

| 维度 | ZCode | Claude Code |
| --- | --- | --- |
| 终端 | `zcode` CLI/TUI | `claude` CLI |
| 桌面 | Electron 桌面应用 | 桌面应用（mac/win，Linux beta） |
| 浏览器 | `zcode --web` 本地 Web UI | claude.ai/code 云端（无需本地环境） |
| 扩展 | skills、UI 插件、MCP、子代理（MCP 与子代理为本会话 CLI 实测） | CLAUDE.md、skills、hooks、MCP、子代理 |

历史判断（已被 2026-10-29 修正）：Claude Code 仍多出的广度功能：云端托管运行、移动端 App、Slack/Channels 集成、Agent SDK、后台并行 agent、云端定时任务、GitHub Actions/GitLab CI 集成。

修正：不能把移动使用、聊天渠道和定时任务整体归为 ZCode 缺失能力。ZCode 已提供手机浏览器远控、微信／飞书 Bot Channel 和本地定时任务；手机远控不等于独立移动 App，本地定时也不等于云端托管。Claude Code 官方概览列有移动 App、云端与本地定时任务、Channels 和 Agent SDK，但未对 ZCode 全面排查的能力不能据此断言缺失。[一手：ZCode 自动化](https://zcode.z.ai/cn/docs/automations)、[一手：Remote Control](https://zcode.z.ai/cn/docs/remote-control)、[一手：Bot Channel](https://zcode.z.ai/cn/docs/bot-channel)、[一手：Claude Code 概览](https://code.claude.com/docs/en/overview)。

#### 成熟度与生态

- Claude Code：2025-02-24 首发为 limited research preview，此后约 20 个月周更级迭代（2.1.x 系列）。
- ZCode：仓库公开版本记录自 2026-09-23（v3.14.3）起，2026-10-19 至 v3.16.2；8.3k stars。开源发生于 2026 年 9 月（媒体一致报道；"开源当日仓库仅两次提交"的说法出自 The Next Web，二手，未核实）。
- 智谱同时在 Claude Code 内运营官方插件市场（zai-coding-plugins，"Z.ai Coding Plugins Marketplace in Claude Code"），GLM 也可服务 Claude Code 用户。

#### 模型层：无法量化

- Claude Code 终端与 IDE 入口支持第三方提供商；智谱提供 GLM Coding Plan 的兼容接口接入教程。不能把“可接 GLM”写成 ZCode 的独有优势，也不能把“有兼容接入方式”外推为任意模型与全部功能都无条件兼容。[一手：智谱 Claude Code 教程](https://docs.bigmodel.cn/cn/coding-plan/tool/claude)、[一手：Claude Code 概览](https://code.claude.com/docs/en/overview)（2026-10-29 复核）。
- ZCode 工具免费，自配智谱服务（GLM Coding Plan 等）、OpenAI 兼容端点或 Anthropic 端点。
- 已核实的同条件对比仅有 GLM-5.3-Flash 与 Claude Haiku 5.5（Haiku 5.5 多数项领先，GDPval-AA v2.1 上 GLM 略高）；这是双方的小模型层，不能外推到 GLM-5.3 旗舰与 Claude 旗舰。

#### 结论

- 历史结论（已被 2026-10-29 修正）：差距存在：打磨时间（约 20 个月对 1 个多月）、功能广度（云端、移动、SDK、定时任务）、社区与生态规模。修正原因：公开仓库历史不等于产品开发时长；功能存在性必须逐项核实，ZCode 已有手机远控、本地定时和聊天渠道，不能把旧清单直接当作当前能力差距。
- 形态差距已对齐：三端入口与核心扩展机制齐备。
- 模型层差距没有已核实数据；日常任务两者均可用，选型取决于模型偏好、预算与网络条件。

### 2026-10-29 追问：既然 Claude Code 能接 GLM，为什么还用 ZCode？

**事实**：智谱官方文档说明如何在 Claude Code 中使用 GLM Coding Plan。ZCode 官网也明确套餐支持 ZCode、Claude Code 等多种工具。因此，GLM 的基础价格、国内服务和模型能力不能单独构成改用 ZCode 的理由。[一手：智谱接入教程](https://docs.bigmodel.cn/cn/coding-plan/tool/claude)、[一手：ZCode 官网](https://zcode.z.ai/cn)。

**具体理由**：ZCode 闲时任务把“不急于开始”换成“不消耗套餐额度”。例如代码库分析、批量注释和文档同步检查可以交给队列。适合已有套餐且有此类工作的人；这是一项套餐权益理由，本次未实测其任务质量，也未核实同模型比较中 ZCode 更强。[一手：闲时任务](https://zcode.z.ai/cn/docs/idle-time-tasks)（2026-10-29 核实，面向订阅用户分批开放）。

适用条件与限制（均据上述闲时任务文档）：

- 需要有效的 ZAI 或 BigModel 个人 Coding Plan；Start Plan 和纯 API Key 模式不支持。团队套餐支持正在开放，具体资格以客户端为准。
- 只支持桌面端本地项目；电脑必须保持唤醒。每天创建数量有上限，队列不承诺开始时间。
- 自动执行及分段续跑不扣套餐额度；用户主动发送的追加消息及其驱动的执行正常计入额度，权限确认仍属于免费自动执行。
- 闲时通道实际使用的模型由服务端统一指定，不能保证使用会话界面显示的自选模型；支持前台子智能体，不支持后台子智能体。

**建议／推断**：如果已经用顺 Claude Code + GLM，又不需要闲时任务或其他经实际验证的 ZCode 工作流，则本次证据不足以支持迁移。官方“深度联调”是厂商表述，不能替代同模型、同仓库、同任务的实测。[一手：ZCode 欢迎页](https://zcode.z.ai/cn/docs/welcome)仅支持其官方定位。
