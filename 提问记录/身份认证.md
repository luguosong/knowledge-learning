# 身份认证

## 综述

主线是"共享秘密向更安全的位置迁移"：明文密码 → 哈希+盐 → 票据/挑战响应（密码不上网络）→ OTP 双因素 → 联邦 SSO → FIDO/Passkey 公钥无密码；每一代收窄上一代的暴露面，WebAuthn（服务器只存公钥、私钥不出设备、签名绑定域名）同时终结钓鱼与拖库。配套层是会话管理（cookie/session/JWT）：认证之后在无状态 HTTP 上延续身份，属基础设施而非新的一代；其弱点（JWT 是 bearer token，泄露即冒用）与密码同属"持有人凭证"，演化方向（DPoP 私钥绑定令牌）与主线一致。

## 2026-09-21 · 用户身份认证技术的演化过程
- **问**：用户身份认证技术是怎么一步步演化过来的？
- **答**：主线是"秘密不断向更安全的位置迁移"：明文密码（1961 CTSS）→ 哈希+盐（1979 Morris & Thompson）→ 票据/挑战响应，密码不上网络（1988 Kerberos、1998 S/KEY RFC 2289）→ 一次性口令双因素（2005 HOTP RFC 4226、2011 TOTP RFC 6238）→ 联邦单点登录（2005 SAML 2.0、2012 OAuth 2.0 RFC 6749、2014 OpenID Connect）→ 公钥抗钓鱼无密码（2012 FIDO 联盟、2014 U2F、2019 WebAuthn/FIDO2、2022 Passkeys）。每一代都修复上一代"共享秘密"的暴露面：WebAuthn 起服务器只存公钥、私钥永不出设备、签名绑定域名，钓鱼与拖库同时失效。
- **信源**：[一手] Morris & Thompson《Password Security: A Case History》https://rist.tech.cornell.edu/26fa/landacker/security/morris-password-security.pdf · RFC 2289/4226/6238/6749 (rfc-editor.org) · SAML 2.0 OASIS 技术总览 https://docs.oasis-open.org/security/saml/Post2.0/sstc-saml-tech-overview-2.0.html · W3C WebAuthn https://www.w3.org/TR/webauthn-3/ · FIDO Alliance https://fidoalliance.org/passkeys/ · [二手] MIT News 讣告（Corbató 与首个密码）https://news.mit.edu/2019/fernando-corbató-obituary-0715

## 2026-09-21 · Cookie/Session/JWT 算不算认证技术
- **问**：cookie、session、JWT 这些算用户身份认证技术吗？
- **答**：算演化史的配套层，但严格分类属于**会话管理**——认证（一次性验明正身）之后，如何在无状态的 HTTP 上延续身份。两条主线：①cookie 载体（1994 Netscape Montulli 为购物车发明，RFC 6265 2011 年标准化，6265bis 草案加 SameSite 等）；②状态放哪的权衡——服务器端 session（可撤销、有状态）vs JWT（RFC 7519 2015，无状态、难撤销）。JWT 本质是 bearer token（谁持有谁能用），泄露即冒用——与密码同属"持有人凭证"弱点；会话层自身的演化方向与认证主线一致：DPoP（RFC 9449 2023）用客户端私钥绑定令牌，偷走也没用。OIDC 的 ID Token 就是 JWT，故这层贯穿第三~六代，是基础设施而非新的一代。
- **信源**：[一手] RFC 6265 https://www.rfc-editor.org/rfc/rfc6265 · RFC 7519 https://www.rfc-editor.org/rfc/rfc7519 · RFC 9449 https://www.rfc-editor.org/rfc/rfc9449 · oauth.net DPoP https://oauth.net/2/dpop/ · [二手] Wikipedia HTTP cookie（1994 起源）https://en.wikipedia.org/wiki/HTTP_cookie
