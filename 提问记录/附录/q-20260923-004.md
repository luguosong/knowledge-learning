### 范围、前置与版本

- **Spring Framework** 提供控制反转（Inversion of Control，IoC）容器、面向切面编程（Aspect-Oriented Programming，AOP）、事务、Web MVC / WebFlux、测试和集成抽象；**Spring Boot** 负责应用启动、自动配置、依赖管理与生产支持；**Spring Data、Security、Cloud 等**是独立项目。先掌握 Framework，才能解释 Boot 和其他项目的行为。[一手] [Framework 目录](https://docs.spring.io/spring-framework/reference/)、[项目目录](https://spring.io/projects)。
- 前置知识：Java SE 的反射、注解、泛型、异常、并发；Maven 或 Gradle；HTTP、Servlet / Filter；SQL、JDBC、数据库事务；JUnit。先能写出不依赖 Spring 的小型服务，再观察 Spring 消除了哪些重复工作。Java 基础路线见 [[Java SE#综述]]；此处只展开 Spring 相关知识。
- 固定一个项目版本做实验，再查该版本文档。JDK 21／25 可用于当前 Spring Boot 4.1 系列（Java 17–26，各线 JDK 支持见 2026-10-15 条目）；若进入 Spring Cloud，必须核对其发布列车与 Boot 的兼容表，使用对应 BOM。[一手] [Boot 系统要求](https://docs.spring.io/spring-boot/system-requirements.html)、[Cloud 兼容表](https://spring.io/projects/spring-cloud/)。

**为什么形成这套框架**：Spring 官方将起点追溯到对早期 J2EE 复杂性的回应。容器把对象创建和装配从业务代码移到配置模型；代理让事务等横切逻辑围绕方法调用组合；MVC 将 Servlet 请求处理拆成可替换组件；Boot 后来用约定和条件配置缩短启动与部署路径。这是对官方历史、设计原则和各组件机制的教学归纳，不表示每层抽象都适合每个项目。[一手] [Spring 历史与设计原则](https://docs.spring.io/spring-framework/reference/overview.html)、[Boot 目标](https://docs.spring.io/spring-boot/)。

### 主线：每阶段学什么、为什么学、如何验收

| 阶段 | 知识点与底层问题 | 通过标准 |
| --- | --- | --- |
| 0．不用 Spring 实现最小服务 | 手动构造对象依赖；用 Java 动态代理包一层调用；Servlet / Filter 分发请求；JDBC 手工开启、提交和回滚事务。由此认识装配、横切逻辑、HTTP 适配与资源管理为何重复且易错。 | 能写一个“创建签章任务”接口，明确对象创建位置、连接归属与失败回滚点。 |
| 1．IoC 与依赖注入（Dependency Injection，DI） | `BeanFactory` 与 `ApplicationContext`；`BeanDefinition`；`@Component` 扫描、`@Configuration` / `@Bean`、`@Import`、配置类方法代理；构造器注入、候选选择、`@Primary`、`@Qualifier`；单例、原型、Web 作用域；懒加载、循环依赖。底层要问：容器如何由定义创建对象、解析依赖并决定生命周期？ | 不依赖 Boot 创建容器；注册两个同类型 Bean，解释消歧；复现构造器循环依赖和单例注入原型的结果。 |
| 2．容器生命周期与扩展点 | `refresh()` 的注册、工厂后处理、Bean 后处理、单例预实例化；实例化、属性装配、初始化、代理、销毁；`BeanFactoryPostProcessor`、`BeanPostProcessor`、`FactoryBean` 的处理对象与时机；`Aware`、事件、`Resource`、`Environment`、类型转换、数据绑定、校验、国际化、Spring Expression Language（SpEL）。 | 为一个 Bean 记录完整创建顺序；写最小后处理器，证明“改 Bean 定义”与“改 Bean 实例”的区别；关闭容器观察清理。 |
| 3．AOP 与代理 | 连接点、切点、通知、切面、Advisor、拦截器链；JDK 动态代理与类代理；代理对象与目标对象；通知顺序；自调用、`final` / `private` 方法边界；Spring AOP 与 AspectJ 字节码织入的差别。为什么学：事务、缓存、异步及部分安全能力依赖方法调用被拦截。 | 给服务方法加计时通知；观察代理类型与调用链；复现 `this.method()` 绕过通知，再改变调用路径验证。 |
| 4．Spring MVC | Servlet、Filter、`DispatcherServlet` 前端控制器；`HandlerMapping`、`HandlerAdapter`、参数解析、数据绑定与校验、`HttpMessageConverter`、返回值处理、`HandlerExceptionResolver`；`@ControllerAdvice`、静态资源、文件上传、CORS、异步请求、WebSocket；HTTP 方法、状态码、内容协商与缓存。为什么学：注解只描述路由，请求如何到方法并形成响应仍由组件链决定。 | 从请求进入 Servlet 到响应写出完整调用链；调试一次参数校验失败、媒体类型不匹配和异常转换。 |
| 5．数据访问与事务 | `DataSource` 与连接池；`JdbcTemplate` / 命名参数、异常转换；`TransactionManager`、`TransactionInterceptor`、`TransactionTemplate`；事务传播、隔离、只读、超时、回滚规则、保存点；物理事务与逻辑事务；线程绑定资源。JPA / Hibernate 与 MyBatis 各有自己的 SQL / 映射机制，不能将其行为都归于 Spring。 | 同一业务分别用 JDBC 原生事务与 `@Transactional` 实现；测试异常回滚、自调用、`REQUIRES_NEW` 占用额外连接、跨线程调用和 `UnexpectedRollbackException`。 |
| 6．Spring Boot | Starter、依赖管理、内嵌服务器、`SpringApplication.run()`；`@SpringBootApplication` 的配置、扫描与自动配置；自动配置候选、`@Conditional`、用户 Bean 使默认配置退让；外部配置优先级、Profile、`@ConfigurationProperties`、配置校验；启动事件、运行器、日志、Actuator、打包与关闭。为什么学：把可重复的装配决策交给条件配置，同时保留覆盖点。 | 去掉一个依赖或加入自定义 Bean，解释自动配置变化；用条件报告定位“不生效”；做一个有条件的最小自动配置。 |
| 7．Spring Security | Servlet 过滤器链、`DelegatingFilterProxy`、`FilterChainProxy`、`SecurityFilterChain`；认证与授权、`SecurityContext`、密码存储、会话、CSRF、CORS、方法级授权、异常入口；按需要学习 OAuth 2.0 资源服务器、OIDC 登录、授权服务器。为什么学：安全决策通常发生在 Controller 之前，且认证不等于授权。 | 画出过滤器与 MVC 的先后顺序；测试匿名、已登录、权限不足、跨站请求和资源访问；验证方法级授权的代理边界。 |
| 8．测试与生产 | 纯单元测试、Spring TestContext、上下文缓存、测试切片、`MockMvc`、`@SpringBootTest`、真实数据库集成测试；Actuator 健康检查、指标与追踪、日志关联、配置与密钥、优雅停机、性能剖析；提前处理（Ahead-of-Time，AOT）和 Native Image 按需深入。为什么学：Spring 应用是否可靠，需在真实装配和失败路径下验证。 | 同一用例具备快速业务测试与至少一个跨 HTTP、数据库边界的集成测试；制造启动失败、连接池耗尽与慢请求，保留证据定位。 |

阶段 1—3 依据：[一手] [IoC 容器](https://docs.spring.io/spring-framework/reference/core/beans.html)、[容器扩展点](https://docs.spring.io/spring-framework/reference/core/beans/factory-extension.html)、[AOP 代理](https://docs.spring.io/spring-framework/reference/core/aop/introduction-proxies.html)。阶段 4—5 依据：[一手] [MVC 处理过程](https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-servlet/sequence.html)、[声明式事务实现](https://docs.spring.io/spring-framework/reference/data-access/transaction/declarative/tx-decl-explained.html)、[事务传播](https://docs.spring.io/spring-framework/reference/data-access/transaction/declarative/tx-propagation.html)。阶段 6—8 依据：[一手] [Boot 自动配置](https://docs.spring.io/spring-boot/reference/using/auto-configuration.html)、[Security 架构](https://docs.spring.io/spring-security/reference/servlet/architecture.html)、[Boot 测试](https://docs.spring.io/spring-boot/reference/testing/spring-boot-applications.html)、[Boot 可观测性](https://docs.spring.io/spring-boot/reference/actuator/observability.html)。

### 横向知识点：贯穿主线

| 主题 | 必须理解的边界和取舍 |
| --- | --- |
| 对象与生命周期 | Bean 默认 `singleton` 是“每个容器、每个 Bean 定义一个实例”，不是 JVM 全局单例；原型 Bean 的销毁不由容器完整管理。单例应审查可变共享状态。[一手] [Bean 作用域](https://docs.spring.io/spring-framework/reference/core/beans/factory-scopes.html)。 |
| 代理与事务 | 默认代理模式下，只有经过代理的调用才触发通知。默认回滚针对 `RuntimeException` 和 `Error`；检查型异常需核对配置与版本。`REQUIRES_NEW` 使用独立物理事务，可能增加连接池压力。[一手] [AOP 代理机制](https://docs.spring.io/spring-framework/reference/core/aop/proxying.html)、[`@Transactional` 设置](https://docs.spring.io/spring-framework/reference/data-access/transaction/declarative/annotations.html)、[传播行为](https://docs.spring.io/spring-framework/reference/data-access/transaction/declarative/tx-propagation.html)。 |
| 线程与上下文 | 命令式事务通常绑定当前线程；新建线程不会自动继承事务。响应式事务使用 Reactor Context，须保持同一响应式流水线。请求、安全和日志上下文也要查各自传播机制。[一手] [声明式事务实现](https://docs.spring.io/spring-framework/reference/data-access/transaction/declarative/tx-decl-explained.html)。 |
| 抽象与实际实现 | Spring 缓存注解不等于具体缓存存储；Spring Data Repository 的方法名查询最终仍由数据模块生成查询，查询性能取决于 SQL、索引和数据库；事务注解不跨远程调用自动提供原子性。[一手] [缓存抽象](https://docs.spring.io/spring-framework/reference/integration/cache.html)、[Spring Data 查询方法](https://docs.spring.io/spring-data/jpa/reference/repositories/query-methods-details.html)、[声明式事务边界](https://docs.spring.io/spring-framework/reference/data-access/transaction/declarative.html)。 |
| 输入与表达式 | 数据绑定应限制可写字段；校验负责输入约束，不代替业务不变量；SpEL 能访问对象和方法，不能把不可信输入直接当作可执行表达式。[一手] [SpEL 求值安全](https://docs.spring.io/spring-framework/reference/core/expressions/evaluation.html)。 |
| 版本与生态 | Boot、Framework、Security、Data、Cloud 各有版本和迁移差异。Spring Framework 6 起使用 `jakarta.*` 命名空间；先锁定 BOM 与参考文档，再比较默认行为，不混用不同主版本的配置示例。[一手] [Framework 概览](https://docs.spring.io/spring-framework/reference/overview.html)、[Boot 系统要求](https://docs.spring.io/spring-boot/system-requirements.html)、[Cloud 兼容表](https://spring.io/projects/spring-cloud/)。 |
| 事件与异步 | `ApplicationEvent` 是应用内事件机制；`@TransactionalEventListener` 可绑定提交或回滚阶段；`@Async` 交给任务执行器运行，默认代理模式也受自调用限制。先说明事件与事务、线程和外部消息投递的边界。[一手] [事务绑定事件](https://docs.spring.io/spring-framework/reference/data-access/transaction/event.html)、[任务执行与调度](https://docs.spring.io/spring-framework/reference/integration/scheduling.html)。 |

### 源码阅读顺序：沿一条请求追，不从仓库第一页读

下列 `main` 分支源码链接用于定位类；实际调试应切换到项目依赖的版本标签，避免把不同版本实现混为一谈。

```mermaid
sequenceDiagram
    participant C as 客户端
    participant F as Servlet Filter 链
    participant S as FilterChainProxy
    participant D as DispatcherServlet
    participant H as HandlerAdapter
    participant P as Service 代理
    participant DB as 数据库
    C->>F: HTTP 请求
    F->>S: 选择 SecurityFilterChain
    S-->>F: 认证授权后放行
    F->>D: 请求分发
    D->>H: 匹配并调用处理器
    H->>P: Controller 调用业务方法
    P->>DB: 事务内访问数据
    DB-->>P: 返回结果
    P-->>H: 返回业务结果
    H-->>D: 写响应或解析异常
    D-->>F: 返回响应
    F-->>C: HTTP 响应
```

图示为典型 Servlet + Spring MVC + Spring Security 路径的教学简化；短路、异常和异步请求会改变路径。[一手] [Security 架构](https://docs.spring.io/spring-security/reference/servlet/architecture.html)、[MVC 处理过程](https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-servlet/sequence.html)。

1. **启动与容器**：从 `SpringApplication.run()` 进入 `ApplicationContext.refresh()`，看 Bean 定义如何注册、工厂后处理器何时执行、Bean 后处理器何时注册、单例何时创建。重点类：`AbstractApplicationContext`、`DefaultListableBeanFactory`、`AbstractAutowireCapableBeanFactory`。[一手] [容器刷新源码](https://github.com/spring-projects/spring-framework/blob/main/spring-context/src/main/java/org/springframework/context/support/AbstractApplicationContext.java)、[BeanFactory 源码](https://github.com/spring-projects/spring-framework/blob/main/spring-beans/src/main/java/org/springframework/beans/factory/support/DefaultListableBeanFactory.java)。
2. **方法增强**：由 `BeanPostProcessor` 生成代理，再跟进入站调用、Advisor 匹配、通知链，最后到目标方法。对照自调用失败与正常跨 Bean 调用。[一手] [容器扩展点](https://docs.spring.io/spring-framework/reference/core/beans/factory-extension.html)、[AOP 代理机制](https://docs.spring.io/spring-framework/reference/core/aop/proxying.html)。
3. **HTTP 请求**：跟进 Servlet Filter → Security Filter → `DispatcherServlet` → `HandlerMapping` → `HandlerAdapter` → Controller → 消息转换 / 异常解析；区分安全过滤器、Servlet Filter、MVC Interceptor 与 AOP 切面各自拦截的位置。[一手] [Security 过滤器链](https://docs.spring.io/spring-security/reference/servlet/architecture.html)、[DispatcherServlet 源码](https://github.com/spring-projects/spring-framework/blob/main/spring-webmvc/src/main/java/org/springframework/web/servlet/DispatcherServlet.java)。
4. **数据提交**：从服务代理进入 `TransactionInterceptor`、`TransactionManager` 和 JDBC 连接；观察事务何时开启、何时提交 / 回滚，以及底层实际 SQL。[一手] [事务实现](https://docs.spring.io/spring-framework/reference/data-access/transaction/declarative/tx-decl-explained.html)、[TransactionInterceptor 源码](https://github.com/spring-projects/spring-framework/blob/main/spring-tx/src/main/java/org/springframework/transaction/interceptor/TransactionInterceptor.java)。
5. **自动装配**：检查自动配置候选文件、条件注解和配置绑定；用条件报告定位某个 Bean 为什么出现或缺席，再决定是否阅读相应自动配置类。[一手] [自定义自动配置](https://docs.spring.io/spring-boot/reference/features/developing-auto-configuration.html)、[自动配置](https://docs.spring.io/spring-boot/reference/using/auto-configuration.html)。

### 最小综合项目与验收

做一个**模拟签章任务管理服务**：提交任务、查询状态、取消任务。先完成原生 Java / Servlet / JDBC 版本，再迁到 Spring Boot。用构造器注入；数据库事务覆盖“创建任务 + 写审计记录”；认证后校验任务归属；对非法请求使用统一异常响应；记录请求关联 ID、指标和健康状态。不要把“审计记录与业务事务同回滚”直接等同于正式审计要求，审计可靠性另按业务标准设计。

按以下失败实验验收：注入两个同类型 Bean；制造构造器循环依赖；让内部方法自调用绕过事务；让检查型异常触发预期之外的提交；在外层事务中执行 `REQUIRES_NEW` 并观察连接池；发送非法 JSON、非法字段、无权限请求；关闭数据库与重启服务；检查条件装配报告、实际 SQL、调用栈、日志与测试结果。每次写下**现象 → 调用链 → 原因 → 修复 → 复测**。这套实验是本路线的教学建议，不是 Spring 官方考核标准。
