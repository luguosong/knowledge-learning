# 身份认证

本领域沿两条线学习。一是认证技术本身的演化，主线是共享秘密不断向更安全的位置迁移；二是认证之后的会话与令牌层。OAuth 协议、密码学基础与 Java 工程实现分开学习。

## 认证技术的演化：共享秘密向更安全的位置迁移

**结论**：每一代认证技术都在修复上一代"共享秘密"的暴露面。主线如下。

```text
+ 明文密码             1961 CTSS
|
+ 哈希 + 盐            1979 Morris 与 Thompson
|
+ 密码不上网络         1988 Kerberos / 1998 S/KEY
|                      （票据、挑战响应）
+ 一次性口令双因素      2005 HOTP / 2011 TOTP
|
+ 联邦单点登录         2005 SAML 2.0 / 2014 OIDC
|
+ 公钥无密码           2019 WebAuthn / 2022 通行密钥
```

**原因**：

- 明文密码直接比对，泄露即失守。哈希加盐把存储端的秘密变成不可逆摘要。
- Kerberos 与 S/KEY 用票据和挑战响应让密码不再穿越网络。
- 基于 HMAC 的一次性密码（HMAC-based One-Time Password，HOTP）与基于时间的一次性密码（Time-based One-Time Password，TOTP）把第二因素变成一次性口令，截获一次无效。
- 安全断言标记语言（Security Assertion Markup Language，SAML）2.0 与单点登录（Single Sign-On，SSO）把认证集中到身份提供方，应用不再各自存密码。
- 公钥无密码一代：Web 认证（Web Authentication，WebAuthn）起服务器只存公钥，私钥永不出设备，签名绑定域名。钓鱼与拖库同时失效。

**记录修正**：早期记录曾把 OAuth 2.0（2012，RFC 6749）直接列为用户认证演化的一代。此归类已于 2026-09-22 修正：开放授权（OAuth 2.0）是授权框架，OpenID Connect（OIDC）才在其上定义身份认证层。

**限制**：

- 演化史中的其余结论未在 2026-09-22 那次核实中重新验证。
- WebAuthn 的域名绑定与公私钥边界不应泛化为"所有攻击均被消除"。

## Cookie、Session 与 JWT：会话与令牌层，不是认证协议

**结论**：三者不等价，也都不能单凭名称视为用户身份认证协议。

- Cookie 是浏览器的状态载体。
- Session 是会话管理机制。
- JSON Web 令牌（JSON Web Token，JWT）是可用于多种场景的声明格式。

**原因**：认证是一次性验明正身；此后的问题是在无状态的 HTTP 上延续身份，这属于会话管理。两条主线：

```text
+ 会话管理：认证之后延续身份
   |
   +-- 载体：Cookie
   |     1994 年 Netscape 的 Montulli 为购物车发明；
   |     RFC 6265 于 2011 年标准化，6265bis 草案补充 SameSite 等。
   |
   +-- 状态放哪：
         +-- 服务器端 Session：可撤销，有状态
         +-- JWT：无状态，难撤销
```

会话层贯穿认证演化的第三至第六代，是基础设施，不是新的一代。

**记录修正（并列）**：

- 旧答：JWT 本质是持有者令牌（Bearer Token，谁持有谁就能使用），DPoP 令牌"偷走也没用"。
- 修正（2026-09-22）：JWT 是格式，不必然按持有者令牌方式使用。OIDC 的 ID 令牌采用 JWT 格式；访问令牌可采用 JWT 或不透明格式。DPoP（Demonstrating Proof of Possession，RFC 9449，2023）用客户端私钥把访问令牌绑定到发送方，但防护有条件：只在攻击者无法取得或调用绑定私钥时成立，客户端已被控制时不保证安全。

**限制**：旧答中的历史日期未在该次核实中重新验证。

## in Action 系列的服务器认证与鉴权书目

**结论**：Manning "in Action" 系列有覆盖服务器认证与鉴权的书，但按视角分册，无一本总纲。

```text
+ 通用服务器模式   > API Security in Action
+ Java 工程实现    > Spring Security in Action（第二版）
+ OAuth 协议深挖   > OAuth 2 in Action
+ IAM 服务器       > 系列内无书
                    （Keycloak 的成书在 Packt）
```

- API Security in Action（2020-11，Neil Madden）：覆盖通用服务器认证与授权模式——认证、授权、审计、限流、加密，Java 示例。
- Spring Security in Action 第一版 2020-10；第二版 2024-04，更新到 Spring Boot 3 与 OAuth2/OIDC。
- OAuth 2 in Action（2017-03）：深挖协议本身。
- 身份与访问管理（Identity and Access Management，IAM）服务器 Keycloak 在 in Action 系列内无书；实际成书是 Packt 的 Keycloak IAM 书（仅二手确认）。
- Microservice Security in Action（2021）：仅二手确认存在，Manning 页面已下架，未核实。

**限制**：API Security in Action 与 OAuth 2 in Action 出版早于 RFC 9700，书中的安全结论需按安全最佳现行实践（Best Current Practice，BCP）校正。
