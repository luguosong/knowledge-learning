# 文章与提问记录维护规范

主题文章是唯一知识正文。问题身份、来源与日期的含义见根目录 GLOSSARY.md。

## 位置与所有权

| 位置 | 内容 | 写入方式 |
| --- | --- | --- |
| `docs/` | 主题文章、导读和补充页 | 人工或 AI 代理维护 |
| 文章开头 | 领域范围和当前理解 | 与正文一起维护 |
| 相关正文附近 | 来源、适用条件、核实及修正历史 | 只刷新实际复核部分 |
| 文章末尾的提问记录 | 原问、约束、身份、日期及正文入口 | 每个问题只有一个主文章 |
| `docs/附件/` | 来源原件、脚本与实验轨迹 | 保留原件及采集边界 |
| `管理/索引.json` | 领域入口与问题元数据 | `sync` 生成，不手改 |
| `管理/兼容链接.json` | 旧领域、旧标题到问题 ID 的映射 | 仅结构维护时修改 |
| `管理/日志/` | 按月维护记录 | 追加 |
| `管理/迁移核对.json` | 统一迁移的冻结清单 | 迁移验收使用，不随知识更新刷新 |

管理文件不放入站点内容导航。反向链接只在临时构建副本中生成。

## 检索与概览

1. 用 `rg` 检索索引中的领域名称与范围。
2. 读取对应文章开头的领域概览，不通读全站。
3. 用 `find` 检索原问题、正文关键词、稳定 ID 或旧标题。
4. 按返回的文章章节读取正文；只沿相关链接继续。

```bash
python 站点/工具/records.py find "缓存 回收" --domain "Linux"
python 站点/工具/records.py find "q-20261027-005"
python 站点/工具/records.py backlinks q-20261027-005
python 站点/工具/records.py backlinks "docs/软件开发/Git.md"
```

命令输出路径相对于 `站点/`。旧标题映射只支持检索，不恢复旧本地路径。

## 范围与综述格式

将以下区域放在文章开头。一个领域只登记一次；多篇文章可以属于同一检索领域。

```markdown
<!-- domain: Git -->
**范围**：版本控制、命令行环境与拉取请求。

**综述**：当前理解、限制和待解问题。至多 600 字符，保持一段。
<!-- /domain -->
```

专题导读可以承载多个领域。领域不要求与专题目录一一对应。

## 提问记录格式

在文章末尾添加以下区域。每个 ID 只出现于一个主文章的提问记录中。

```markdown
## 提问记录

### q-20261101-005

- **原题**：2026-11-01 · 原始问题标题
- **问**：原问题及必要约束。
- **领域**：Git
- **首次**：2026-11-01
- **更新**：2026-11-01
- **正文**：[相关章节](#相关章节)
- **关联**：[相关问题](其他文章.md#q-20261027-007)
```

正文链接可以指向多个章节或补充页。关联字段可省略，其他字段必须保留。

提问记录只允许上述字段及可选的追问字段。跨行内容缩进两个空格；不要在记录后追加正文、表格或来源清单。

ID 使用首次日期和当日未用序号，序号至少三位。追问保留原 ID 与原标题；语义独立的问题才新增 ID。

首次日期与实际知识更新日期分别保存。首次问题的更新日期等于首次日期；迁移、排版和构建不刷新知识日期。

提问记录不保存答案、来源清单或完整推导。将这些内容写在相应主题章节。

## 来源、核实与修正

- 每项结论必须能定位到支持它的具体资料。保留一手、二手和未核实标注。
- 在相关正文附近保存核实日期、复核范围、版本和适用条件。部分复核不刷新整篇文章的日期。
- 来源采集日期、文件哈希和 Git 提交时间不替代核实日期。
- 修正旧结论时保留修正日期、原因和证据。条件或版本不同的结论分别说明。
- 来源原件按版本保存；采集说明保留原 URL、机构、版本、采集日期和哈希。
- 迁移保留历史核实状态，不宣称重新核实。实际问答仍须遵守根指引的联网规则。

## 结构变更与检查

1. 先写好目标文章，再删除被替代文章。
2. 随正文移动提问记录；每个原 ID 必须仍有唯一主文章。
3. 同时更新正文入口、问题关联、导读、导航和附件链接。
4. 执行以下命令，修复本次引入的错误。

```bash
python 站点/工具/records.py sync
python 站点/工具/records.py check
python 站点/工具/build.py
```

`check` 检查格式、唯一身份、日期、范围、链接和索引。脚本不证明事实正确，也不检查远程网页是否仍有效。

正文入口必须指向知识章节或补充页，不能指回提问记录。检索返回实际命中的目标；示例中的 Markdown 标题不参与章节划分。

本地链接使用标准 Markdown。含空格的路径使用 `%20`；问题入口使用稳定 ID，章节锚点采用保留中文的规则。

`sync` 先校验再写索引，使用排他锁及单文件替换。锁不约束编辑器；同一批文章由一个维护者写入。

## 迁移验收与恢复

统一迁移使用 `python 站点/工具/records.py audit` 核对冻结清单。该命令检查原问、身份、日期、来源和附件哈希；不用于后续日常问答。

大规模改动前保存快照、文件清单和哈希。恢复时先保存当前状态，再在独立目录核对快照，最后选择恢复范围。

历史维护资料保存在 `管理/历史/`，其中旧路径只描述当时的结构。统一迁移前的完整快照位于 Git 忽略的 `.scratch/站点统一迁移/`。
