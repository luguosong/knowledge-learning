# 站点维护规范

## 内容归属

- `docs/` 中的主题文章是唯一知识正文。术语按 [项目术语表](../GLOSSARY.md) 使用。
- 调整表现形式时，保留结论、条件、量值、引用和知识关系。
- 需要修正事实时，核实一手资料后直接更新对应正文及其证据记录。
- 提问记录、范围、来源与日期格式见 [记录维护规范](管理/记录维护规范.md)。
- 自动整理的文章落位与结构操作按 [curate-site](../.claude/workflows/curate-site.js) 执行。

## 图表

- 流程、结构、演化和交互图统一使用 Mermaid，以 `mermaid` 代码块保存。
- 对照数据使用 Markdown 表格。命令和算式保留适合其内容的代码块。
- 新增、修改或迁移图表前，必须读取并执行 [mermaid-visualizer](../.agents/skills/mermaid-visualizer/SKILL.md)。上游执行标准为 [axtonliu 的 mermaid-visualizer](https://github.com/axtonliu/axton-obsidian-visual-skills/tree/main/mermaid-visualizer)。
- 本次触及内容中的已有图表执行同一标准。同步调整与图表有关的图例。
- 长标签和注释按语义拆分，保持技术标识符、版本号、量值和单位完整。

## 共享渲染

- 渲染入口见 [zensical.toml](zensical.toml)，主题兼容样式统一维护在 [diagrams.css](docs/stylesheets/diagrams.css)。
- 沿用技能的浅色配色与站点的浅色画布。用容器 CSS 变量统一节点、文字、箭头和注释的颜色。
- 宽图保留文字字号，在容器内横向滚动。
- 当前 Zensical 将 SVG 放入封闭的 Shadow DOM。浏览器检查工具须保留根节点引用或使用调试接口；普通 `.mermaid svg` 查询不能证明渲染失败。

## 验证

1. 对照一手证据及原有文章核对改动。完成标准：结论、条件、量值、引用和图表关系均有依据；提问记录可定位正文。
2. 逐幅执行技能质量清单。完成标准：本次触及的图表全部通过清单检查。
3. 依次运行 `python 站点/工具/records.py sync`、`check` 和 `python 站点/工具/build.py`。完成标准：结构检查与严格构建通过；源文章没有反向链接生成块。
4. 使用站点实际加载的 Mermaid 运行时逐幅渲染。完成标准：本次触及的图表全部生成有效 SVG，且无解析或运行错误。
5. 检查浅色、深色主题及 1440 px、390 px 视口。完成标准：以下各项均通过。

   - 文字对比度不低于 4.5:1。
   - 节点与注释文字均不越框。
   - 技术标识符显示完整。
   - 宽图保持文字字号，且可以横向滚动。
